## 1. 问题形式化

### 1.1 任务模型（借自 `01-...md §B` 的 sync step 时序）

每个 RL 任务 `T_i` 的一个 step 节奏如下（相位循环）：

```
GEN(N)  →  sleep_replicas  →  [old_logp / ref / values / critic / actor 反向]  →  update_weights(N→N+1)  →  GEN(N+1)
 推理忙     推理卡 sleep            训练忙、推理卡空泡（主战场）                      推理卡唤醒+权重重载
```

记号：

| 符号 | 含义 | 来源/备注 |
|------|------|----------|
| `phase_i ∈ {GEN, TRAIN}` | 任务 i 当前相位 | GEN=generate_sequences 在跑；TRAIN=sleep 后的反向段。`01-...md §B` |
| `tp_i` | 任务 i 的 rollout tensor-parallel size | 决定凑卡粒度（必须 tp 倍数） |
| `r_i` | 任务 i 当前 replica 数（DP 路） | `r_i × tp_i` = 任务 i 当前占用推理卡数 |
| `t_g_i` | 任务 i 的 GEN 时长历史统计 | 见 §2.2 空泡预测器 |
| `t_t_i` | 任务 i 的 TRAIN 时长历史统计 | 同上 |
| `w_i` | 任务 i 当前 step 权重版本（step 号 N） | on-policy 一致性锚点，§3 |
| `P` | 公共池空闲裸卡集合 | 每张卡带 node 归属、最近加载的任务/权重（软状态） |

### 1.2 动作空间（调度器每轮决策）

```
A. LEND(借出方 j, 借入方 i, 卡数 k, 权重版本 w_i)
   — 借出方 j 从自己的空泡卡里给借入方 i 分 k 张卡
   — k 须为 tp_i 的倍数（凑 replica），且满足借入方 PG 拓扑（STRICT_PACK 同 node，`01-...md §A3`）
   — 借入方在 k 张卡上重拉 vLLM 实例 + 加载 w_i + warmup（冷启动，由借入方承担，§5.2 P1-3）

B. RETURN(借入方 i, 卡数 k)
   — 借入方归还 k 张卡（GEN 结束 / 被抢占 / 主动释放）

C. PREEMPT(借出方 j, 借入方 i, 卡数 k)
   — 借出方 j 进入 GEN、自己要用卡，强制收回此前借给 i 的 k 张
   — 仅在借入方 generation 批次边界允许（§3.2），避免半 batch 脏数据

D. NOOP
```

### 1.3 目标函数

```
min  Σ_i  makespan_i                          # A1 端到端耗时下降
max  E[推理卡利用率] = 忙碌推理卡时 / (忙碌+空泡)推理卡时   # A2 利用率提升
min  E[空泡占比]                              # A3 空泡下降
s.t. on-policy 红线（§3）永不违反              # A4 正确性 0 回归（硬约束）
```

A1/A2/A3 之间在"全捐 + 裸卡 + on-policy"叠加下**不必然一致**（§6.2）：降低 makespan 靠加速借入方 GEN，提升利用率靠填借出方空泡——两者通常一致，但当冷启动亏损时，填空泡反而降 makespan。**故 on-policy 红线 + 冷启动门槛是硬约束，目标在其内做。**

## 2. 第一性约束（算法的锚）

### 2.1 冷启动刚性不等式（核心锚，对应 §6.2 / G6）

> **借调净收益 = 借入方因加速省下的 GEN 时长 − 冷启动成本 `C_start(tp_i)` ≥ 0，才借。**

其中 `C_start = vLLM init + 权重加载(w_i) + warmup`。**权重加载是刚性项**：on-policy 下每 step 权重都变，借入卡上加载的是借入方**当前 step** 权重；卡上残留的至多是上 step 权重，借回时仍须全量灌当前 step 权重。故冷启动软化至多省 `init`（复用引擎），省不了权重加载。**不能夸大工程软化作用**——这条印证 `00-alignment §6.2` 的判断，调度器不依赖"把冷启动压到极低"。

推论：调度器主防线 = **只在空泡够长时借**（空泡预测门槛，§4.1），不是"想办法降低冷启动"。冷启动软化是次要工程项，不在算法层解决。

### 2.2 on-policy 红线（正确性硬约束，对应 §3 on-policy 约束）

借入卡产出的样本，其权重版本必须与借入方 trainer **当前 step 严格对齐**。算法层须保证：

1. **借入即载当前权重**：LEND 动作携带 `w_i`（借入方当前 step 号），借入卡实例加载 `w_i` 才能产出样本。`[x]`
2. **样本标注 step 版本**：借入卡产出的样本标 `step=N`，进入借入方 replay_buffer，须在借入方 `update_weights(N→N+1)` 前完成 generation + 被 sample 取走。`[x]`
3. **跨 step 归须重载**：若借调跨越借入方 `update_weights`（即借入方已进入 step N+1 的 GEN，而借来卡上仍是 step N 权重），归还/继续使用前必须重新加载 `w_{N+1}`——**这会再付一次权重加载，与冷启动刚性耦合**。算法上避免跨 step 借调（§4.3）。`[~]`
4. **抢占在批次边界**：PREEMPT 只允许在借入方 generation 一个 **完整 batch 边界**（整 prompt 完成或整批完成），被抢 batch 作废（借入方该 step generation 量减少，但 on-policy 正确性不受损——只是吞吐下降）。`[x]`

### 2.3 收益上限公式（相位互补律，对应 G3）

> **借调收益上限 = P(任一时刻存在相位互补任务对) × 可借卡数 × max(0, 空泡时长 − C_start)**

若所有任务同相位（GEN 撞 GEN、TRAIN 撞 TRAIN），池里要么没卡可借、要么没人需要。**多任务"不定时加入"（§5.1）天然带一定错峰，但是否够取决于 G3**：

- G3 = 天然错峰良好 → 被动响应式借调即可（算法形态 F1-b）。
- G3 = 天然撞车严重 → 调度器首要职责变为**主动相位编排**（错峰），借调退居兑现错峰收益手段（算法形态 F1-a）。

这是算法形态的根本分叉，**取决于 G3**，§5 列为变体。

## 3. 借调窗口的物理边界（基于 step 时序，`01-...md §B`）

借调窗口 = 借出方空泡与借入方 GEN 的**交集时长**：

```
借出方 j 视角：  sleep_replicas ─────────── (推理卡空泡) ─────────── update_weights
                                                              ↑ 借出方要回收卡做权重同步+唤醒，借调强制终止
借入方 i 视角：  GEN(N) ───────────────────────────────────────→ sleep_replicas
                                                              ↑ 借入方自己 GEN 结束要 sleep，借调自然终止
                   ↑ 借调开始                       ↑ 借调结束
                   └──────── 借调窗口 = min(借出方空泡剩余, 借入方 GEN 剩余) ────────┘
```

- **借调开始条件**：借出方 j 已 `sleep_replicas`（推理卡空泡已形成）AND 借入方 i 处于 GEN（需要卡）AND 冷启动门槛满足（§4.1）。
- **借调结束条件（三选一触发）**：
  - (a) 借出方 j 到 `update_weights`（借出方自己要用卡做权重同步+唤醒）→ 触发 PREEMPT/RETURN。
  - (b) 借入方 i 到 `sleep_replicas`（借入方 GEN 结束）→ 触发 RETURN。
  - (c) 借入方 i 到 `update_weights`（跨 step）→ 若借调须延续，须重载新权重（§2.2.3），否则 RETURN。
- **物理边界硬约束**：借出方 `update_weights` 会 abort replicas + release kv_cache + build PG + 跨进程同步权重（`base.py:470`）——**借出方此时物理上要重载自己的权重，借出去的卡必须在此之前归还**。算法须保证借调窗口在借出方 `update_weights` 前留足"归还+借出方自己权重同步"的时间余量。

## 4. 调度算法核心组件

### 4.1 空泡预测器（算法前提）

**输入**：phase 事件流（GEN_START / GEN_END / TRAIN_START / TRAIN_END 边界，来自 L1 phase 可观测层——那是工程项，不在本文档）、历史 step 时序。

**输出**：

| 量 | 定义 | 用途 |
|----|------|------|
| `gap_lend(j)` | 借出方 j 空泡剩余时长预测 | 决定借调窗口上界 |
| `gap_borrow(i)` | 借入方 i GEN 剩余时长预测 | 决定借调窗口下界 |
| `C_start(tp_i)` | 借入方 i 的冷启动成本估计 | 门槛判定 |

**预测方法**：历史时序统计（EWMA/分位数），不用复杂模型。预测误差直接变冷启动亏损——预测越准，门槛越激进；预测越差，门槛越保守（留更多安全余量）。**误差惩罚设计是算法 knob**。

> 注：verl 无实时 phase 暴露（`01-...md §E13`），预测器依赖 phase 事件流——这是算法能工作的**工程前置**，不在本文档解决。算法层**假设 phase 事件流可得**（带已知延迟/丢消息），并在决策中计入观测延迟。

### 4.2 借调触发判定（门槛，算法核心）

每次 phase 事件到达，对每个候选 (借出方 j, 借入方 i) 对，执行：

```
def should_lend(j, i):
    if phase_j != TRAIN:           return False   # 借出方未在空泡
    if phase_i != GEN:             return False   # 借入方不在 GEN
    if not_contributes_to_0(j):    return False   # §5.2 P1-2 全捐前提（借出方有空闲卡）

    window = min(gap_lend(j), gap_borrow(i))
    if window <= C_start(tp_i) + margin:          # 冷启动刚性不等式（§2.1）
        return False                              # 借了净亏，NOOP

    # 借出方 update_weights 前须留归还+权重同步余量（§3 物理边界）
    if gap_lend(j) - window < lend_reclaim_margin(j):
        return False

    if no_idle_packing_topology(i, P):             # §4.5 凑卡可行性（tp 倍数+同 node）
        return False

    return True
```

门槛 `margin` = 安全余量，吸收预测误差。**这是最关键的 knob**：太小→借了又抢、净亏冷启动；太大→空泡填不满。最终值依赖 G6（冷启动基线）+ 预测器误差特性，**待回填**。`[~]`

### 4.3 借入方选择（匹配，给谁）

多个借出方空泡 + 多个借入方 GEN 时，解一个匹配。**目标**：最大化总净收益 `Σ max(0, window − C_start)`。

简化为贪心（实际可加权匹配/匈牙利，但 PoC 先贪心）：

```
def match(candidates):
    # candidates = [(j, i, k_feasible, window, net_gain)]
    sorted = sort by net_gain desc
    matched = []
    for (j, i, k, w, g) in sorted:
        if j 仍在空泡 and i 仍要卡 and 池有 k 张可凑:
            apply LEND(j, i, k, w_i)
            matched.append(...)
    return matched
```

**排序权重候选（公平 vs 收益，§6 防饥饿 knob）**：

| 权重方案 | 行为 | 适用 |
|---------|------|------|
| 纯净收益 `net_gain` desc | 收益最大化，可能饿死小任务 | G3 错峰好、不愁卡 |
| `net_gain / 累计获借量` desc | 越少被借过越优先（防饥饿） | 全捐到 0、多任务（§5.2 P1-2） |
| 带优先级 `priority_i × net_gain` | 紧急任务优先 | 有 SLA/优先级场影 |

倾向：**MVP 用纯净收益 + 防饥饿因子**（§6），不引入人为优先级（§5.2 P1-5 后置）。`[~]`

### 4.4 借出方选择（从谁借）

多个借出方都能借时，优先选：

1. **空泡最长且最不可能被自己提前打断的**（`gap_lend(j)` 大且方差小）→ 借调窗口稳。
2. **同 node 优先**（满足借入方 STRICT_PACK 拓扑，省跨 node 凑卡失败）。
3. **权重版本最近的**（若借入方 w_i 与卡上残留权重同源，可省 init——次要优化，§2.1 已说不省权重加载）。`[~]`

### 4.5 借调量决策（借多少）

```
def decide_k(j, i, P):
    # 借入方 i 能用的卡须为 tp_i 倍数，且落在同 node（STRICT_PACK）
    feasible = max k s.t. k % tp_i == 0
                and exists node n with >= k idle cards in P
                and k <= gap_borrow(i) 能消化的量   # 借太多借入方 GEN 提前结束，浪费
    # 上界：不要借超过"借入方 GEN 能用完的量"，否则冷启动摊销变差
    k_useful = min(feasible, k_that_just_fills_gap_borrow(i))
    # 防饥饿：留足借出方 j 自己 GEN 时借回的最低保留（§6）
    k = min(k_useful, lendable(j) - reserve_for_self(j))
    return k
```

- `tp_i` 倍数 + 同 node 是硬约束（`01-...md §A3` STRICT_PACK、§3 vLLM 在线改 TP 不可行）。
- `tp_i` 大 → 凑卡难、冷启动权重大 → 可借性差。是否允许调度器**建议任务用小 tp** 以提高可借性？依赖 G4（同构性）、G6（冷启动基线），列为变体 F3，**不进 MVP**。`[~]`

### 4.6 归还/抢占决策（何时收回）

```
on event 借出方 j 到 update_weights 前置点（gap_lend(j) ≈ lend_reclaim_margin）:
    PREEMPT(j, all_borrowers_of_j)    # 借出方要用卡了，全收回

on event 借入方 i 到 sleep_replicas（GEN 结束）:
    RETURN(i, all_borrowed_by_i)      # 借入方不需要了，自然还

on event 借入方 i 到 update_weights（跨 step）且借调须延续:
    # on-policy 红线 §2.2.3：重载 w_{N+1}，再付一次权重加载
    if gain_after_reload > C_reload:  重载续借
    else:                             RETURN(i)
```

**抢占安全边界**（§2.2.4）：PREEMPT 只在借入方 generation **批次边界**执行。若借入方正卡在半 batch，**等 batch 完成**再抢（代价：借出方多等一个 batch 时长；收益：不产脏样本）。这是 on-policy 与借调抢占的折衷 knob。`[x]`

## 5. 算法变体 / 策略族

### F1. 调度器形态（取决于 G3）

| 变体 | 描述 | 侵入度 | 收益上限 | 依赖 |
|------|------|--------|----------|------|
| F1-a 主动相位编排 | 插手任务启动时机 / step 节奏，主动制造相位互补 | 高（与"任务不定时加入"语义张力） | 高 | G3=撞车严重 |
| F1-b 被动响应 | 任务自然跑，空泡出现才借调 | 低 | 看 G3 天然错峰 | G3=错峰好 |
| F1-c 渐进 | 先 F1-b 打通机制，后加 F1-a | 低→高 | 递进 | — |

**倾向 F1-c**（与 `00-alignment §5.2` "先打通机制"一致）：被动版能先验证"借调收益不等式"是否成立（G6 的试金石），主动编排作为机制跑通后的增量。`[~]`

### F2. 空泡预测器精度（取决于 L1 工程前置 + G3 相位稳定性）

- (a) phase 事件 + EWMA 时序统计：MVP 足够，误差由 margin 吸收。
- (b) 自适应门槛：margin 随预测误差历史动态调整（误差大→margin 大→保守）。
- (c) 不预测，保守阈值：固定窗口门槛，实现最简，浪费最多。

倾向 (a)→(b) 渐进。`[~]`

### F3. 借调粒度与 tp 建议（取决于 G4、G6）

- MVP：固守 DP 扩容整卡（tp 倍数），不碰在线改 TP（§3 不可行）。
- 优化项（后置）：允许调度器**建议任务用小 tp** 以提高可借性 / 降低单次冷启动权重占比。依赖 G4 同构性、G6 冷启动基线。`[~]`

## 6. 防饥饿与公平（全捐到 0 的副作用，§5.2 P1-2）

全捐到 0 → 任务自己 GEN 时可能池里也被借空（别人借走还没还）。算法须有：

1. **最小借回权**：任务 i 进入 GEN 时，池有卡则优先满足 i 的最小 throughput 需求 `min_k(i)`，剩余才分给他人。`min_k(i)` 是"保证 i 不饿死的最低卡数"knob。
2. **累计借出/借入记账**：长期记账，借出多的任务在竞争池资源时有优先权（贡献-回报平衡）。
3. **饥饿检测**：若任务 i 连续 K 个 step GEN 时拿不到 `min_k(i)`，强制从最大借入方 PREEMPT 回收。

**张力**：最小借回权 vs 全捐效益最大化（§5.2 P1-2）——`min_k(i)` 设太大→池化效益降；设太小→饿死。是 fairness knob，**待 G3 量化后定**。`[~]`

> 注：§5.2 P1-5 原说"核心调度策略后置"。本文档是把策略从后置拉到前台讨论**算法骨架**，**数值阈值与 fairness knob 仍待 G3/G6 回填后收敛**——与 P1-5 不冲突，是它的细化。
